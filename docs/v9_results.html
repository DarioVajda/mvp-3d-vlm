Interpretation

What this means

  • Most of the lead over SpatialStack comes from data and training, not fusion. LoRA alone, with no geometry, reaches 66.5. That is only 1.0 below SpatialStack-4B and above its published no-geometry fine-tune (64.8), on a smaller model. Geometry then adds 3.4, close to SpatialStack's own +2.8.
  • Geometry does a specific job. Absolute distance +9.3 and relative direction +7.1 carry it, with room size +2.9 behind. Counting and object size don't benefit.
  • Additive and cross-attention are tied, again. The difference is -0.38 [-1.05, 0.31], and it was -0.20 in v7. Additive is simpler and has 50.4 M fewer trainable parameters, so nothing here justifies cross-attention yet.
  • The frame mix is a small general gain. Additive +1.0, cross-attention +0.8, LoRA +1.2. All three arms gain about the same, so it helps the model generally, not geometry in particular. The 128-frame evals will show whether it also helps at longer inputs.
  • The biggest remaining room is route planning (40) and absolute distance (58). Route planning has no training data here, so added data looks like the cheapest test.

Limits. Two seeds per arm, and one for v9 LoRA until the seed 0 rerun finishes. Intervals cover question sampling, not seeds. SpatialStack is one released checkpoint evaluated through its own lmms-eval pipeline, rescored here with our scorer (67.45, against 67.53 in lmms-eval), and I did not verify its prompts match ours token for token. Only one checkpoint of each v9 run was evaluated, so it wasn't picked by test score. I checked that no training video appears in VSI-Bench: file names and ScanNet scene ids show zero overlap. There is no MMSI result for v9, and the 128-frame evals are still running, so neither is included.
