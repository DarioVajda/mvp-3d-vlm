# How spatial / 3D-aware VLMs fuse geometry-encoder features into the LLM, and whether any use an auxiliary alignment or latent-prediction loss (2024–2026)

Conventions: arXiv ids are given once per model; "Sec./Table/Eq." refer to the arXiv HTML version fetched on 2026-10-26 (version noted where it matters). Every number below was read from the paper via the linked page unless marked **[local]** (from this repository's own reproductions) or **[unverified]**. OpenReview review threads could not be fetched (bot challenge), so no reviewer/rebuttal material is included; see Gaps.

## Model-by-model record: geometry encoder, fusion mechanism, LLM layers, objective, fine-tuning regime, headline numbers

### Takeaway
Across ~25 models, the dominant recipe is: frozen VGGT (or CUT3R / StreamVGGT / AnySplat) → 2×2 merge + 2-layer MLP → **element-wise addition to the visual tokens before the LLM**, trained with next-token loss only and a fully-tuned LLM. The exceptions are (a) cross-attention before the LLM with 2D tokens as queries (VLM-3R, Stream3D-VLM, Spa3R, VLM-IE3D's internal IEA), (b) multi-layer additive injection into early LLM layers (SpatialStack: layers 0–2; GUIDE: first 6, gated; GAP-MLLM: "multi-modal DeepStack"; ViPS: five layers), and (c) supervision-only designs with no geometry input at inference (3DRS, MVRD, Think-with-3D, GASP, Spatial Forcing, GLaD, GeoWorld-VLM, Ross3D, Cambrian-S).

### Cited Findings

**A. Input-level additive injection (geometry → visual tokens before the LLM), next-token loss only**

- **VG-LLM (arXiv 2505.24625, NeurIPS 2025).** Encoder: VGGT-1B "encoder and the fusion decoder", prediction heads dropped, frozen; per-frame patch features computed jointly over all frames (Sec. 3.1; no specific layer named). Fusion: 2×2 patch merge + two-layer MLP, then patch-wise addition T^S = T^G' + T^V' before the LLM (Sec. 3.1). Objective: next-token only, "no task-specific heads" (Sec. 3.2.1). Regime: MLLM backbone unfrozen (Qwen2.5-VL-3B/7B), vision encoder, VGGT and connector frozen; 1 epoch, batch 64, lr 1e-5, 8×H100 (Sec. 4). The paper does not say "LoRA"; "unfrozen" implies full fine-tune **[inference]**. VSI-Bench (Table 8, S1+S2 data): Qwen2.5-VL-7B fine-tuned 59.8 → VG-LLM-8B 62.2. — [arXiv 2505.24625v3](https://arxiv.org/html/2505.24625v3)
- **Spatial-MLLM (arXiv 2505.23747).** Encoder: spatial encoder initialised from the VGGT feature backbone (alternating frame-wise / global attention), outputs e_3D, camera features and register tokens; only e_3D is fused; VGGT camera/depth heads used only for space-aware frame sampling (Sec. 3.1–3.2). Fusion: e_3D folded to the 2D token grid (Eq. 3), "lightweight connector" (Eq. 4); Appendix B.2: both streams go through a two-layer MLP and are fused by **element-wise addition**, after 2×2 spatial and 2-frame temporal merging so token counts match; patch size 14 for both encoders. Objective: SFT cross-entropy (Eq. 6) then GRPO with KL β=0.04 (Eq. 7), rewards = format + relative accuracy / exact match / fuzzy match; no auxiliary alignment loss (Sec. 3.3). Regime: both encoders frozen, connector + LLM trained; Adam, 1 epoch, batch 16, peak lr 1e-5; RL 1,000 steps lr 1e-6 (Sec. 4.1). LoRA vs full not stated. VSI-Bench micro avg 48.4 (Qwen2.5-VL-3B base 30.6) (Table 1). — [arXiv 2505.23747](https://arxiv.org/html/2505.23747)
- **Video-3D LLM (arXiv 2412.00493).** No learned geometry encoder: depth + extrinsics/intrinsics back-projected, average-pooled per ViT patch, sinusoidal-encoded, **added** to video features, e_vis = e_img + e_coord (Eq. 5). Objective: CE (Eq. 6) + InfoNCE grounding loss on object proposals (Eq. 7). Regime: LLaVA-Video-7B, 1 epoch, batch 16, lr 1e-5 LLM / 2e-6 vision encoder. ScanQA EM 30.1 / CIDEr 102.1, SQA3D EM 58.6 (Table 1). PE ablation (Table 3): no 3D-PE → Sin PE moves Scan2Cap C@0.5 31.03→83.76 but ScanQA EM only 30.03→30.09. — [arXiv 2412.00493](https://arxiv.org/html/2412.00493)
- **LLaVA-3D (arXiv 2409.18125).** 3D position (nearest-neighbour depth + known intrinsics/extrinsics, DUSt3R for video, App. F) → learnable 2-layer MLP embedding **added** to CLIP patch tokens, X3D' = Xp' + P' (Eq. 1). Objective: LM loss + grounding-decoder loss (DIoU + InfoNCE) (App. A). Regime: stage 1 full multi-task tuning, 1 epoch, lr 1e-5 LLM / 2e-6 ViT; stage 2 decoder only, 40 epochs. ScanQA CIDEr 103.1, SQA3D EM 60.1 (Table 1). Table 9: 3D patches add only +0.4 ScanQA / +0.3 SQA3D but +13.3 MMScan QA, +54.4 Scan2Cap. — [arXiv 2409.18125v3](https://arxiv.org/html/2409.18125v3)
- **SpatialRGPT (arXiv 2406.01584, NeurIPS 2024).** Depth map (off-the-shelf model, ref. [43] = Depth Anything per the reference list) passed through the **same image encoder**, then a **separate depth-to-language connector** initialised from the RGB connector; `<region>`/`<depth>` placeholders replaced by region RGB/depth embeddings (Sec. 3.3). The paper argues that "simply concatenating RGB and depth features may negatively impact performance" but shows no ablation of that claim. Objective: auto-regressive generation only. Regime: depth connector trained alone (lr 1e-4) with RGB connector + LLM frozen, then instruction tuning (Sec. 3.4, App. H.2). Depth ablation (Table 1, 7B vs 7B-rgb): qualitative avg 91.78 vs 89.80; direct distance 41.2 vs 35.1; but RGB-only wins vertical distance (53.8 vs 51.9) and width (51.9 vs 49.6). — [arXiv 2406.01584v3](https://arxiv.org/html/2406.01584v3)
- **SpatialVLM (arXiv 2401.12168, Jan 2024)** is a data-generation framework (2B spatial VQA examples on 10M images); the abstract reports investigating "VLM architecture" but describes no geometry encoder injected into the LLM. — [arXiv 2401.12168](https://arxiv.org/abs/2401.12168)
- **GPT4Scene (arXiv 2501.01428, Jan 2025)** is "purely vision-based": a BEV image rendered from the video with consistent object-ID markers, concatenated with marked frames as image input; no geometry encoder, no auxiliary loss (abstract). — [arXiv 2501.01428](https://arxiv.org/abs/2501.01428)
- **3D-LLM (arXiv 2307.12981, July 2023, out of the 2024–2026 window)** obtains 3D features "from rendered multi-view images" with 2D VLM backbones plus a "3D localization mechanism" (abstract). — [arXiv 2307.12981](https://arxiv.org/abs/2307.12981)

**B. Cross-attention before the LLM (2D visual tokens as queries, geometry tokens as keys/values)**

- **VLM-3R (arXiv 2505.20279, CVPR 2026).** Encoder: CUT3R, frozen; per-frame tokens F'_t (context-aware spatial tokens) and pose/"view" tokens z'_t concatenated into Z_3D (Eq. 1); point-map and pose heads are not used as inputs; frames resized to 432×432 to match the CLIP token count (Sec. 4.1). Fusion: single-head scaled dot-product cross-attention, Q = CLIP visual tokens H_v, K/V = Z_3D (Eq. 2), residual H'_v = H_v + H_attn (Eq. 3), then a two-layer projector, then concatenated with text and fed to the LLM; App. A.1/A.2: "a one-layer cross-attention block", `--tune_fusion_block True`. Objective: "the same learning objective as LLaVA-NeXT-Video" (next-token); no auxiliary losses. Regime: LoRA r=128, α=256, lr 2e-5, cosine, per-device batch 1 × grad-accum 8, concluded after 1 epoch on H200s (Sec. 5.1, App. A.2). VSI-Bench avg 60.9 (Table 1). — [arXiv 2505.20279v5](https://arxiv.org/html/2505.20279v5)
- **Stream3D-VLM (arXiv 2606.06891, June 2026).** Encoder: StreamVGGT-1B frozen; K geometry tokens G_t plus a camera token c_t, concatenated and projected by a two-layer MLP (Eq. 4). Fusion (VSFI, Eq. 5): "stack of cross-attention blocks" (count not stated), 2D tokens as queries, 3D tokens as K/V, residual; placed between vision encoder and LLM. Objective: L = λ·L_stream (CE over `<SEP>`/`<END>` decision tokens) + L_LM; no geometry loss (Eq. 3). Regime: vision encoder + StreamVGGT frozen, VSFI + LLM fully trainable (LoRA not mentioned), AdamW, 1 epoch; Qwen2.5-VL-3B/7B (Sec. 5.1). VSI-Bench avg 65.9 (8B), 55.2 (4B) (Table 3). — [arXiv 2606.06891](https://arxiv.org/html/2606.06891)
- **Spa3R / Spa3-VLM (arXiv 2602.21186).** A separate 6-layer encoder (256 learnable queries) and decoder are pre-trained with a JEPA-inspired "predictive spatial field" objective: regress frozen-VGGT last-layer patch tokens and frozen-DINOv3 ViT-L/16 tokens at novel target viewpoints, L1 + cosine per patch (Sec. III-A/B, Eq. 14–15). For the VLM (Qwen2.5-VL-3B) the frozen Spa3R latent is read through a **Residual Cross-Attention Adapter** with the VLM's visual features as queries; the adapter MLP is zero-initialised and added residually; adapter + LLM trained (Sec. III-C). VSI-Bench 58.6 (Table I). — [arXiv 2602.21186](https://arxiv.org/html/2602.21186)
- **VLM-IE3D (arXiv 2607.21595).** Implicit tokens from AnySplat's fusion decoder; explicit tokens (depth by default; point maps / Gaussians tested) from its heads; an Implicit–Explicit Attention block (IGT queries, EGT K/V, residual, Eq. 2); the resulting 3D tokens are then **added** to the 2D tokens, T = T2D + T3D (Eq. 3); Qwen2.5-VL-3B; encoders frozen, backbone trained; no auxiliary loss described; VSI-Bench avg 47.6 (Table 4). — [arXiv 2607.21595](https://arxiv.org/html/2607.21595)

**C. Multi-layer injection inside the LLM (DeepStack-style)**

- **SpatialStack (arXiv 2603.27437, CVPR 2026).** Encoder: VGGT-1B frozen; patch tokens from aggregator layers {11, 17, 23} (0-indexed; camera/register tokens removed); VGGT's default DPT taps are {4, 11, 17, 23} and layer 4 was dropped after "preliminary testing" with no numbers (Sec. 4.2, 5.3). Merger (Eq. 4, App. A.2): RMSNorm → 2×2 window merge → two-layer MLP. Injection (Eq. 5): H^(j)' = H^(j) + G_{l_j} for LLM layers j ∈ {0,1,2}, mapping Geo-L11→L0, Geo-L17→L1, Geo-L23→L2; restricted to the vision-token slice via a scatter mask (Eq. 15–16), applied at prefill. Objective: next-token CE only (Eq. 6); "No auxiliary objectives or task-specific losses are introduced" (Sec. 4.2). Regime (Table B, App. C): trainable = "Language tower + fusion modules", LoRA never mentioned; AdamW, lr 1e-5, cosine, 3% warmup, 1 epoch, effective batch 64, 4–8 frames, bf16, DeepSpeed ZeRO-2, 32×A100; data 212k (SPAR 140k, LLaVA-Hound 38.3k, VLM-3R ScanNet 31.1k, VSI app-order 1.9k; Table A). VSI-Bench 67.5 on Qwen3.5-4B, 60.9 on Qwen2.5-VL-3B (Fig. 5); fine-tuned no-geometry Qwen3.5 64.76 (Table 2). — [arXiv 2603.27437v3](https://arxiv.org/html/2603.27437v3)

- **GUIDE (arXiv 2604.05695v2).** Encoder: VGGT-1B frozen; layer 23 added to the visual tokens at the LLM input (Eq. 6–7) and layers {8, 11, 14, 17, 20, 23} (stride 3, after excluding the first ⌊K/4⌋ layers; Eq. 4) injected into the **first 6 LLM layers**, added to the output hidden states at visual-token positions. Gating: per-token scalar gate σ(MLP(h)) (Eq. 8) and per-layer tanh(α_l) gate (Eq. 9); h_out = h + G_layer ⊙ (G_tok ⊙ g) on visual tokens only (Eq. 10–11). Objective: not stated beyond standard training; no auxiliary alignment loss mentioned. Regime: Qwen3-VL-4B/8B LLM + projector + gates trained; vision encoder, VGGT, original connector frozen; Adam, batch 64, lr 1e-5, 8×A100. VSI-Bench: 55.6 (controlled data) vs reproduced VG-LLM-5B 51.7; 71.5 / 72.1 with VLM-3R + VSI-590K data (Table 1). MMSI-Bench 30.2 / 29.6 / 29.4 (Table 2). — [arXiv 2604.05695](https://arxiv.org/html/2604.05695)
- **GAP-MLLM (arXiv 2603.16461v2).** Encoder: VGGT-1B frozen; layers 5, 11, 17 fused at intermediate depth and layer 24 as primary input (Sec. 4.1). Fusion: per-layer sigmoid gate g = σ(MLP([T^V', T^G'])), output g⊙T^V' + (1−g)⊙T^G' (Eq. 2–3); final-layer fused tokens are the decoder input; intermediate fused tokens are added to the hidden states of early decoder layers ("multi-modal DeepStack"; the specific decoder layers are not listed). Pre-training objective: predict the (x, y, z) coordinate and semantic label of a visually prompted pixel as text — **not** a feature-alignment loss (Sec. 3.2). Regime: Qwen3-VL-2B (labelled 3B in tables), encoders frozen, LLM + fusion trained, 1 epoch, lr 1e-5. No VSI-Bench reported. — [arXiv 2603.16461](https://arxiv.org/html/2603.16461)
- **ViPS / "Beyond Single Expert" (arXiv 2607.15054).** Five experts (VGGT, DepthAnything3, TraceAnything, Wan2.1, RADIO) replaced by "Efficient Prior Proxies" trained with an L2 alignment loss to the expert features (Eq. 4); priors pass through zero-initialised convs (Eq. 6), are softmax-weighted by an MLP on the final instruction token (Eq. 5), summed (Eq. 7) and **added element-wise to the projected image tokens at five LLM layers** (Sec. 2.2). Regime: vision encoder frozen, LoRA on the LLM, projector/zero-convs/weight-MLP/proxies trainable, 1 epoch, 32 frames. VSI-Bench 63.8 (Qwen2-VL-7B) (Table 1). — [arXiv 2607.15054](https://arxiv.org/html/2607.15054)

**D. Supervision-only (geometry used as a training target, not as input)** — see the next key question for details: 3DRS, MVRD, Think-with-3D, GASP, Spatial Forcing, GLaD, GeoWorld-VLM, Ross3D, Cambrian-S, Vid-LLM.

### Inferences
- Among the models that inject geometry *inside* the LLM (SpatialStack, GUIDE, GAP-MLLM, ViPS), all use addition, all restrict injection to the **earliest** decoder layers (0–2 or 0–5), and two of them (GUIDE, ViPS) found gating or zero-initialisation necessary for stability. None injects via cross-attention inside the LLM.
- The two best-documented fusion-operator ablations on 3D tasks (VG-LLM Table 7; GAP-MLLM Table 8) disagree about cross-attention vs addition, and both are measured on ScanRefer / Scan2Cap / video detection rather than VSI-Bench. Only Stream3D-VLM (Table 6) ablates the operator on VSI-Bench.
- "Full vs LoRA" is rarely stated explicitly; the papers that are explicit about LoRA are VLM-3R (r=128), ViPS, MVRD (r=128) and GASP (attention-only LoRA), while SpatialStack, VG-LLM, Spatial-MLLM, GUIDE, Stream3D-VLM describe the "language tower"/"LLM backbone" as trainable without mentioning LoRA.

### Gaps
- VG-LLM, Spatial-MLLM, SpatialStack, GUIDE and Stream3D-VLM never state "full fine-tuning" verbatim; the inference comes from "unfrozen"/"trainable language tower" plus the absence of LoRA.
- VG-LLM and Spatial-MLLM do not name which VGGT aggregator layer feeds the connector; the local README notes that Spatial-MLLM's connector uses the last aggregator layer **[local, from code inspection, not the paper]**.
- The CVPR 2026 supplement of SpatialStack returned HTTP 403 and could not be checked for additional ablations.

## Key question 1: Does any of these models use an auxiliary alignment / latent-prediction loss between LLM hidden states and 3D features, or a shared LLM–geometry embedding space?

### Takeaway
None of the injection models (SpatialStack, VLM-3R, VG-LLM, Spatial-MLLM, GUIDE, Stream3D-VLM, LLaVA-3D, Video-3D LLM, SpatialRGPT, GPT4Scene, SpatialVLM) use any loss beyond next-token (plus grounding InfoNCE / GRPO where noted). A separate, growing line does exactly what the question asks — regress LLM hidden states (final or intermediate layer, visual-token positions) onto frozen VGGT features with cosine / MSE / Frobenius losses — but always as *supervision without geometry input* (3DRS, MVRD, Think-with-3D, Spatial Forcing, GLaD, 3D-Tokens, ViPS proxies, GeoWorld-VLM), and the two papers that compared "align hidden states" against "inject features" (Spa3R Table V; 3D-Mix Table 1) found injection stronger.

### Cited Findings

**Injection models: no auxiliary loss**
- SpatialStack: "No auxiliary objectives or task-specific losses are introduced" (Sec. 4.2); loss is Eq. 6 cross-entropy. — [arXiv 2603.27437v3](https://arxiv.org/html/2603.27437v3)
- VLM-3R: trained with "the same learning objective as LLaVA-NeXT-Video"; no depth/point/alignment loss described (Sec. 4.1). — [arXiv 2505.20279v5](https://arxiv.org/html/2505.20279v5)
- VG-LLM: all 3D tasks cast as text generation, no task-specific heads (Sec. 3.2.1). — [arXiv 2505.24625v3](https://arxiv.org/html/2505.24625v3)
- Spatial-MLLM: CE (Eq. 6) + GRPO (Eq. 7); no alignment loss (Sec. 3.3). — [arXiv 2505.23747](https://arxiv.org/html/2505.23747)
- GUIDE: no loss beyond standard training stated; Stream3D-VLM: L_stream + L_LM only (Eq. 3); GAP-MLLM: text-coordinate prediction pretraining, "not an explicit alignment loss" (Sec. 3.2). — [GUIDE](https://arxiv.org/html/2604.05695), [Stream3D-VLM](https://arxiv.org/html/2606.06891), [GAP-MLLM](https://arxiv.org/html/2603.16461)

**Hidden-state → geometry-feature alignment losses (supervision only, no 3D input at test time)**
- **3DRS (arXiv 2506.01946, NeurIPS 2025).** Student = the MLLM's final per-pixel visual embedding "taken after the text decoder" (Sec. 2.1.1), projected by a two-layer MLP_align; target = per-pixel features of a frozen 3D foundation model (VGGT or FLARE), average-pooled to the MLLM grid; L_align = −(1/NHW) Σ cosine similarity (Sec. 2.2.2); L_total = L_CE + L_align with no stated weight. Teacher features are precomputed offline and are **not** fed as input; 3D coordinates still enter as a positional encoding (Sec. 2.1.1). Base LLaVA-NeXT-Video-7B, all parameters tuned (Qwen2-VL: projector + LLM only), batch 16, lr 1e-5 LM / 2e-6 ViT, 32 frames. Teacher ablation (Table 4, ScanRefer Acc@0.25): VGGT 62.9, FLARE 62.1, DINOv2 59.8, MAE 59.1, SigLIP2 58.2. Supervised-layer ablation (Table 6): last layer 62.9, 3rd-last 61.7, 5th-last 61.4, 10th-last 59.1. ScanQA CIDEr 104.8 vs Video-3D LLM 102.1; SQA3D 60.6 vs 58.6 (Table 1). VSI-Bench avg 45.9 (Table 2). The paper's own limitation: the correspondence loss "mainly targets view equivariance", so the range of captured 3D properties is limited (Sec. 6). — [arXiv 2506.01946v2](https://arxiv.org/html/2506.01946v2)
- **MVRD, "Multi-View Relational Distillation" (arXiv 2608.10864).** Reproduces 3DRS-style per-token feature distillation (cosine on projected features vs stop-gradient VGGT, L_SFT + λ L_FD, Eq. 1) on LLaVA-Video-7B-Qwen2 with VLM-3R data: VSI avg **57.0 vs 57.7 for SFT alone**; geometric sub-tasks improve (Abs. Dist. 43.6→51.3) but Appr. Order collapses 38.5→19.6 and Obj. Size 70.8→68.0 (Table 1, row "3DRS*"); a text-grounded detection probe shows precision dropping across layers (Fig. 2b). Proposed fix: match the N×N cosine-similarity matrix of multi-view patch tokens to VGGT's, with row-wise negative Pearson correlation, γ = 0.5 (Sec. 4, Table 8), distilled at LLM layer 20 of 28 (Table 4: L7 53.9, L14 57.3, L20 59.9, last 59.8, SFT 57.7); LoRA r=128, α=256. MVRD 59.9, + dual-pathway LoRA 60.4 vs VLM-3R 60.9 (Tables 2–3). Other backbones (Table 6): InternVL3-8B SFT 50.3 / feature-distill 57.0 / MVRD 58.7; Qwen2.5-VL-7B SFT 56.1 / feature-distill **55.5** / MVRD 56.1 / +dual 59.8. — [arXiv 2608.10864v1](https://arxiv.org/html/2608.10864v1)
- **Think with 3D / 3DThinker (arXiv 2510.18632v4).** Hidden states from the **last** VLM layer at k "3D placeholder" tokens inside the chain of thought (Eq. 3) → projector conditioned on image-encoder patch features (Eq. 4) → VGGT **last aggregator layer** features; loss ‖F_proj − F_3D‖²_F (Eq. 5), λ_3D = 0.1, λ_text = 1 (Eq. 9); then GRPO with a cosine-similarity 3D reward r_3D (Eq. 12). VGGT is training-time only; at inference the projector + VGGT DPT head serve only to visualise the latent (Sec. 4.4). Ablation (Table 11, MindCube-Tiny, Qwen2.5-VL-3B): w/o L_3D 54.1 vs 62.7. Latent size 12 best; 32 → 25.1, 64 → 15.5 (Table 5); placing the latent mid-think drops to 42.0 vs 74.3 (Table 6). With 237K curated SFT + 57K RL samples: VSI-Bench 59.1 (3B) / 63.7 (7B), MMSI 41.9 / 43.3 (Table 2). Full vs LoRA not stated. — [arXiv 2510.18632](https://arxiv.org/html/2510.18632)
- **GASP, "Beyond 3D VQAs" (arXiv 2605.30231, FAIR).** No 3D encoder; a 2-layer MLP correspondence head reads visual-token hidden states from **all** LLM layers (28 for Qwen2.5-VL-7B, 32 for LLaVA-NeXT-Video-7B), trained with InfoNCE over ground-truth DL3DV point tracks (Eq. 5) + a relative depth-consistency loss (Eq. 6–8); L = L_LM + 0.3 L_corr + 1.0 L_depth (App. B); head discarded at inference; LoRA on W_Q/W_K/W_V/W_O only (rank 512 LLaVA / 128 Qwen), lr 1e-4, 3 epochs. VSI-Bench object count: Qwen SFT 33.8 → 41.6; LLaVA 23.5 → 52.5; All-Angles camera pose 34.1 → 52.8 (Table 1). Layer ablation (Table 4): all-layer supervision "best and most consistent", but layers 25–32 beat all-layers on All-Angles for LLaVA (39.1 vs 38.1). — [arXiv 2605.30231](https://arxiv.org/html/2605.30231)
- **Spatial Forcing (arXiv 2510.12276v2, VLA, cs.RO).** Visual-token hidden states at **layer 24 of 32** of the VLM backbone (OpenVLA-OFT / π0) → BatchNorm + 2-layer MLP → negative cosine similarity to VGGT transformer-backbone latents sampled at each token's pixel location with a positional embedding (Eq. 3); L = L_action + α L_align (Eq. 4); inference identical to a plain VLA (Sec. 2.3). Layer ablation (Table 2, LIBERO avg SR): layer 1 94.6, 8 95.7, 16 93.8, **24 96.9**, 32 94.8; base 92.7. Target ablation: SigLIP 94.0, DINOv2 94.1, VGGT w/o PE 94.7, VGGT 96.9. — [arXiv 2510.12276v2](https://arxiv.org/html/2510.12276v2)
- **GLaD (arXiv 2512.09619, VLA).** **Final-layer (32/32)** LLaMA-2-7B hidden states at image-token positions → 2-layer MLP → 2048-d VGGT features, **MSE** (Eq. 4); L = L_VLA + λ L_distill, λ not reported (Sec. III-B1); VGGT frozen, supervision only. Table III: VGGT teacher 94.1 vs Pi3 86.1 (LIBERO avg); aligning layer 24 instead of 32 gives 92.6; "early weighted fusion" (injecting instead of aligning) 84.0. Sec. V-C: explicit depth-map supervision "caused training divergence"; contrastive supervision did not beat baselines (no numbers). — [arXiv 2512.09619](https://arxiv.org/html/2512.09619)
- **3D-Mix (arXiv 2603.24393, VLA).** Pilot study (Table 1, Qwen3-VL-4B, SIMPLER avg / LIBERO avg) compares explicit injection with implicit alignment: base 57.81 / 96.50; **Gated fusion (appended VGGT tokens with sigmoid gate) 68.23 / 98.05**; Concat fusion 60.42 / 97.75; Spatial Forcing (cosine alignment at an intermediate layer) 58.85 / 97.72; 3D-Tokens (learnable `<|vggt|>` token with cosine alignment loss) 56.25 / 97.64; Middle-layer injection 51.82 / 97.82; CrossAttn fusion 56.25 / 83.45; Early fusion 44.53 / 86.45. Freezing VGGT is "comparable to or better than fine-tuning" it (Sec. 5.3, Fig. 3a). Gains shrink on the stronger RoboBrain2.5-8B (+1.05 SIMPLER, Table 2). — [arXiv 2603.24393](https://arxiv.org/html/2603.24393)
- **GeoWorld-VLM (arXiv 2605.16713v2).** Aligns **post-projector** features (what the frozen LLM consumes), not LLM hidden states, with cosine loss (Eq. 5) to block-24 DiT features of a camera-conditioned video world model, plus a normalised-MSE preservation loss (Eq. 6); λ_align 0.10, λ_preserve 0.05; LLM frozen, only ViT + projector + heads trained. **Latent-prediction / reconstruction objectives attached to the LLM (no geometry encoder)**
- **Ross3D (arXiv 2504.01901, ICCV 2025).** No geometry encoder (3D PE from depth + poses as in Video-3D LLM, App. A.1). ### Inferences
- The field has split cleanly: injection papers never add an alignment loss, and alignment papers never inject. No paper combines SpatialStack/VG-LLM-style injection with a hidden-state→VGGT regression term, so the interaction is untested.
- Where the LLM layer for alignment was ablated, the winner is deep-but-not-last (Spatial Forcing 24/32; MVRD 20/28 ≈ last) or last (3DRS, GLaD, Think-with-3D), with early layers clearly worse (3DRS 10th-last 59.1; MVRD L7 53.9). This is the opposite end of the network from where injection papers add geometry (layers 0–5).
- Plain per-token feature regression onto VGGT is fragile for language-heavy tasks (MVRD: Appr. Order 38.5→19.6; GeoWorld-VLM: DINOv3 teacher harmful; GLaD: depth-map supervision diverged), which is why the 2026 papers moved to relational (MVRD), contrastive-correspondence (GASP) or world-model (GeoWorld-VLM) targets.

- No OpenReview reviews/rebuttals could be read (api2.openreview.net and openreview.net/forum both return a browser-verification challenge). Forum ids found for later manual retrieval: VG-LLM `oUYmk8WaG0` (NeurIPS 2025), 3DRS `KQuVaVUPL6` (NeurIPS 2025), Spatial-MLLM `RnXS7aK4rK`, Vid-LLM `l1cLdEjESj` (ICLR 2026 oral), "Does Your 3D Encoder Really Work?" `dTzu5vpQvs` (ICLR 2026 submission).
- Loss weights are unreported for 3DRS (implicitly 1), GLaD (λ "tuned on validation"), Spatial Forcing (α in an appendix not fetched), Cambrian-S LFP (App. F not fetched).
- Spa3R's alignment is done by a separate encoder/decoder, not by the LLM; no paper was found that trains the LLM's own hidden states with a JEPA-style predictor against VGGT features *while* also injecting VGGT features.

## Key question 2: Cross-attention (Flamingo / Perceiver / Q-Former style) vs additive or concatenative injection — what do ablations say?

### Takeaway
Cross-attention for geometry appears only *before* the LLM (VLM-3R, Stream3D-VLM, Spa3R, VLM-IE3D) and never as Flamingo-style gated blocks inside the LLM. Ablations conflict: VG-LLM (3D grounding/captioning) and GAP-MLLM (detection) favour addition/gating over 1–3-layer cross-attention; Stream3D-VLM (VSI-Bench), Spa3R (VSI-Bench) and VLM-IE3D favour cross-attention over addition/concat. Concatenation+MLP loses to both in every ablation found.

### Inferences
- The disagreement tracks the task: cross-attention wins on VSI-Bench-style relational QA (Stream3D-VLM, Spa3R) and loses on dense grounding/detection (VG-LLM, GAP-MLLM) where per-patch spatial alignment of the two token grids matters and addition preserves it exactly.
- All cross-attention ablations use 1–3 vanilla (ungated) blocks before the LLM with trainable LLM weights; the Flamingo configuration (gated xattn-dense blocks interleaved inside a frozen/LoRA LLM, Perceiver-resampled K/V) has not been tested for geometry in any paper found.
- Gating is the recurring enabler for anything beyond input-level addition (GUIDE token+layer gates; GAP-MLLM sigmoid mixing; ViPS zero-init convs; 3D-Mix sigmoid gate), which suggests that the stability of injected geometry, not the operator per se, drives many of the reported differences.

### Gaps
- No paper reports a parameter-matched comparison between cross-attention and addition; the cross-attention variants in VG-LLM Table 7 and Stream3D-VLM Table 6 have unstated parameter counts.
- No ablation of *how many* or *which* LLM layers receive cross-attended geometry exists; the only layer-count ablations are additive (GUIDE Table 4; SpatialStack Table 5).

## Key question 3: Negative results — has geometry injection hurt a strong VLM baseline, and what was it attributed to?

### Takeaway
Yes, in several specific forms: (i) VGGT (scale-free, permutation-equivariant) hurt metric and order tasks in VLM-3R (room size 63.7→54.0, appearance order 38.5→34.5); (ii) ungated or deep-layer injection fell below the input-level baseline in GUIDE; (iii) per-token feature distillation lowered the SFT baseline in MVRD and GeoWorld-VLM; (iv) every geometry-augmented model loses a few points on general benchmarks (BLINK, Video-MME, CV-Bench 2D); (v) the margin over a data-matched fine-tune is small (SpatialStack +2.8, VG-LLM +2.4, VLM-3R +3.2) and shrinks on stronger bases (3D-Mix).

### Inferences
- The attributions cluster into four causes: (1) scale/order information missing from the encoder (VGGT normalisation, permutation equivariance); (2) interference when adding geometry into layers that already hold mixed representations (SpatialStack, GUIDE, 3D-Mix middle-layer); (3) loss of vision–language alignment when hidden states are pulled toward geometry features (MVRD, GeoWorld-VLM); (4) the LLM ignoring the geometry because language priors suffice (Does-Your-3D-Encoder, GASP App. D).
- No paper reports geometry injection hurting the *overall* VSI-Bench average of a strong VLM, but several show it hurting specific sub-tasks (room size, appearance order, object size, rel. distance) and general benchmarks, and the gain over a data-matched fine-tune is consistently 2–4 points.

### Gaps
- A head-to-head negative on a frontier-class base (Qwen3-VL-8B or larger) with SpatialStack/VG-LLM-style injection was not found; GUIDE's Qwen3-VL-8B is only compared with its own 4B and VG-LLM.
- 3D-Mix's negative numbers are for robot policies (SIMPLER/LIBERO), not spatial QA.

### Inferences
- The per-task pattern supports the local plan's expectation that relative direction and relative/absolute distance are where geometry should show, while appearance order and room size are the canaries for a scale-free, order-agnostic encoder (VGGT): VLM-3R's VGGT run lost 9.7 on room size and 4.0 on appearance order, and GUIDE's room-size gain (+7.5) came only with gating.
- Cambrian-S reaching 67.5 with no geometry encoder (data + latent frame prediction) sets the bar: the same average as SpatialStack-5B, which argues that most of the VSI-Bench gain in injection papers is data-driven, consistent with SpatialStack's own +13.9 (data) vs +2.76 (geometry) decomposition.

### Gaps
- SpatialStack's per-task numbers for its data-matched no-geometry fine-tune (64.76 avg) were not in the fetched text, so the geometry-only increment per task is unknown for the best-performing model.
- VLM-3R's Table D is the only per-task VGGT-vs-CUT3R comparison found; no paper reports DUSt3R/MASt3R or Fast3R features injected into an LLM with VSI-Bench per-task results.
- Cambrian-S Appendix F (LFP loss weighting ablation) was not fetched, so whether the latent-prediction objective itself changes VSI-Bench is unverified.
